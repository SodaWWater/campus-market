# 00 项目章程

## 项目名称

- 英文名：`campus-market-platform`
- 中文名：校园二手交易平台
- 副标题：基于 Spring Boot 的校园二手商品交易与运营管理平台

## 项目定位

本项目由当前 `campus-market-admin` 升级而来，定位为一个**单体模块化的校园二手交易平台**。项目面向校内学生的闲置物品交易场景，覆盖用户注册登录、商品发布、图片上传、商品审核、商品浏览、下单、模拟支付、订单完成、评价、举报和后台运营管理。

本项目追求的是“商业项目完整度”，不是“高并发企业级架构”。重点是业务闭环完整、状态流转清楚、数据库设计合理、接口权限明确、能本地部署、能页面演示、能写进简历并在面试中讲清楚。

## 目标用户

| 角色 | 说明 | 核心诉求 |
| --- | --- | --- |
| 游客 | 未登录用户 | 浏览在售商品、查看商品详情、注册登录 |
| 普通用户 USER | 校内学生，可同时作为买家和卖家 | 发布商品、浏览商品、收藏、下单、模拟支付、评价、举报 |
| 管理员 ADMIN | 平台运营人员 | 审核商品、管理分类、处理举报、管理用户和订单、查看数据看板 |

## 核心业务闭环

### 买家交易闭环

```text
浏览商品 → 查看详情 → 收藏/咨询 → 创建订单 → 模拟支付 → 线下交付 → 确认完成 → 评价
```

### 卖家发布闭环

```text
完善资料 → 发布商品 → 上传图片 → 提交审核 → 审核通过上架 → 被下单 → 完成交易
```

### 后台运营闭环

```text
管理员登录 → 审核商品 → 管理分类 → 处理举报 → 管理用户/订单 → 查看数据看板 → 操作留痕
```

## 技术边界

| 类型 | 设计选择 |
| --- | --- |
| 架构 | Spring Boot 单体模块化，不做微服务 |
| 后端 | Java 17/21、Spring Boot 3、Spring Security 6、JWT、MyBatis-Plus |
| 数据库 | MySQL 8，强一致交易数据以 MySQL 为准 |
| 缓存 | Redis，仅缓存分类、热门商品、浏览量、未读消息数等非强一致数据 |
| 文件存储 | V1 使用本地 `uploads/` 目录，后续可升级 MinIO |
| 前端 | V1 原生 HTML/CSS/JS 用于演示，V4 可升级 Vue 3 + Element Plus |
| 文档 | Swagger/OpenAPI、README、设计文档、测试计划、面试指南 |
| 部署 | 本地启动优先，Docker Compose 可选启动 MySQL/Redis |

## 明确不做

1. 不做微服务、服务注册、网关和配置中心。
2. 不做分布式事务、分布式锁、秒杀、高并发架构。
3. 不接入微信、支付宝、银行卡等真实支付。
4. 不做复杂 RBAC 菜单权限，只保留 `USER` 和 `ADMIN` 两类角色。
5. 不做真实物流配送，默认校园内线下交付。
6. 不做 WebSocket 实时聊天，V1/V3 使用普通 HTTP 站内消息。
7. 不做 Elasticsearch，搜索使用 MySQL 条件查询。
8. 不引入 RabbitMQ、Kafka 等消息队列。
9. 不做 Kubernetes 部署。
10. 不写“高并发、分布式、微服务、秒杀”等与项目不匹配的描述。

## 演示目标

1. 游客可浏览商品列表和详情。
2. 用户可注册登录、完善资料、发布商品、上传图片。
3. 管理员可审核商品，审核通过后商品进入在售状态。
4. 买家可下单、模拟支付、确认完成并评价。
5. 用户可收藏商品、发送站内消息、举报违规内容。
6. 管理员可处理举报、下架商品、查看数据看板。
7. 通过 Swagger 和页面演示完整流程。

## 简历目标

简历可描述为：

> 基于 Spring Boot 3 设计并实现校园二手交易平台，覆盖商品发布审核、图片上传、商品浏览、下单、模拟支付、订单完成、评价、举报处理和后台运营管理。系统使用 Spring Security 6 + JWT 实现登录鉴权，MyBatis-Plus 操作 MySQL，Redis 缓存分类与热门商品，围绕商品状态机和订单状态机实现完整交易闭环。
