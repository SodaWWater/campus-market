# 13 开发路线图

本路线图是后续 Codex 代码生成的阶段边界。不要一次性实现全部功能。

## V1：最小交易闭环 + 商品审核

目标：能演示从用户发布商品到买家完成订单的完整流程。

功能：

1. 注册登录、JWT 鉴权。
2. 用户资料查看和修改。
3. 本地图片上传。
4. 商品发布，默认 `PENDING_AUDIT`。
5. 管理员审核通过/驳回。
6. 游客商品列表和详情。
7. 我的商品。
8. 创建订单，商品锁定。
9. 模拟支付，订单支付，商品售出。
10. 取消未支付订单，商品恢复在售。
11. 完成订单。
12. 我的订单。
13. 简单原生 HTML 页面。

验收标准：

1. 买家能购买卖家发布且审核通过的商品。
2. 商品审核前不可购买。
3. 创建订单后商品变为 `LOCKED`。
4. 支付成功后订单变为 `PAID`，商品变为 `SOLD`。
5. 未支付订单取消后商品恢复 `ON_SALE`。
6. 并发下单只有一个成功。

不要做：

1. 不做消息、评价、举报。
2. 不做 Vue 完整前端。
3. 不做真实支付。
4. 不做复杂后台。

## V2：后台运营增强

目标：后台更像运营管理平台。

功能：

1. 分类管理完善。
2. 后台数据看板。
3. 用户管理和禁用启用。
4. 商品管理和强制下架。
5. 订单管理。
6. 管理员操作日志。

验收标准：

1. ADMIN 可查看用户、商品、订单、统计数据。
2. 后台关键操作写入 `admin_operation_log`。
3. USER 不能访问 `/api/admin/**`。

## V3：用户互动闭环

目标：补齐交易前后的互动能力。

功能：

1. 收藏商品和我的收藏。
2. 站内消息和未读数。
3. 交易评价。
4. 用户评价列表。
5. 举报提交和后台举报处理。

验收标准：

1. 收藏数正确变化。
2. 消息可发送、查询、标记已读。
3. 只有完成订单可以评价。
4. 举报可被管理员处理并留痕。

## V4：前端体验升级

目标：从演示页面升级为更完整用户体验。

功能：

1. Vue 3 + Vite + Element Plus 用户端。
2. Vue 3 后台管理端。
3. 登录态拦截器。
4. 商品列表、详情、发布、订单、后台审核等页面。

验收标准：

1. 前端可完成 V1-V3 主要流程。
2. 页面调用接口和 `06-api-design.md` 一致。

## V5：工程化和面试材料

目标：项目可部署、可展示、可讲解。

功能：

1. Docker Compose 启动 MySQL/Redis。
2. GitHub Actions 编译检查，可选。
3. README 启动说明。
4. Swagger 接口说明。
5. 测试脚本和演示脚本。
6. 简历项目描述。
7. 面试问答文档。

验收标准：

1. 本地一键导入 SQL 并启动。
2. 文档和代码一致。
3. 面试问题能和代码位置对应。
