# 01 产品需求文档

## 产品目标

将当前简单后台系统升级为“校园二手交易平台”，重点体现：

1. 用户侧交易闭环：浏览商品、收藏、下单、模拟支付、完成订单、评价。
2. 卖家侧经营闭环：发布商品、上传图片、提交审核、查看订单。
3. 后台运营闭环：商品审核、分类维护、举报处理、用户管理、订单管理、操作留痕。
4. 工程完整度：统一鉴权、统一返回、参数校验、异常处理、数据库初始化、接口文档、前端演示。

## 用户角色

| 角色 | 权限边界 |
| --- | --- |
| 游客 | 可浏览在售商品列表和商品详情；不可收藏、下单、发布、评价、举报 |
| 普通用户 USER | 可作为买家或卖家，管理个人资料、商品、订单、收藏、消息、评价、举报 |
| 管理员 ADMIN | 可审核商品、管理分类、处理举报、管理用户和订单、查看数据看板 |

## 用户端功能

| 功能 | 说明 | 优先级 |
| --- | --- | --- |
| 注册登录 | 账号、密码、昵称、手机号注册；登录后返回 JWT | P0 |
| 用户资料 | 维护昵称、手机号、头像、学校、专业、年级、个人简介 | P0 |
| 商品列表 | 游客可浏览；支持关键词、分类、价格区间、成色筛选 | P0 |
| 商品详情 | 展示图片、标题、描述、价格、卖家、浏览量、收藏数 | P0 |
| 商品发布 | 登录用户发布商品，填写分类、价格、成色、地点、图片 | P0 |
| 商品审核 | 发布后进入 `PENDING_AUDIT`，管理员通过后才可售 | P0 |
| 图片上传 | 使用本地 `uploads/` 存储，返回图片 URL | P0 |
| 创建订单 | 对 `ON_SALE` 商品创建订单并锁定商品 | P0 |
| 模拟支付 | 生成支付记录，订单变为 `PAID`，商品变为 `SOLD` | P0 |
| 取消订单 | 未支付订单可取消，商品恢复 `ON_SALE` | P0 |
| 完成订单 | 线下交付后确认完成 | P0 |
| 收藏商品 | 收藏、取消收藏、查看我的收藏 | P1 |
| 站内消息 | 买卖双方围绕商品或订单留言 | P1 |
| 评价交易 | 完成订单后买家评价卖家和商品 | P1 |
| 举报 | 举报违规商品、用户、消息或订单 | P1 |

## 管理员功能

| 功能 | 说明 | 优先级 |
| --- | --- | --- |
| 商品审核 | 审核通过或驳回待审核商品，写审核日志 | P0 |
| 分类管理 | 新增、修改、启用、禁用分类 | P0 |
| 商品管理 | 查询商品、强制下架违规商品 | P0 |
| 订单管理 | 查看订单状态，不直接改价 | P1 |
| 用户管理 | 查询用户、禁用/启用用户 | P1 |
| 举报处理 | 处理用户举报，保存处理结果 | P1 |
| 数据看板 | 展示用户数、商品数、订单数、待审核数等 | P1 |
| 操作日志 | 记录管理员审核、下架、禁用用户等关键操作 | P1 |

## 功能优先级

| 优先级 | 定义 | 功能范围 |
| --- | --- | --- |
| P0 | V1 必须实现，支撑交易演示 | 登录注册、用户资料、图片上传、商品发布审核、列表详情、下单、支付、取消、完成、我的商品、我的订单、简单前端 |
| P1 | V2/V3 实现，提升完整度 | 分类管理、看板、收藏、消息、评价、举报、操作日志 |
| P2 | 时间充足再做 | Vue 完整前端、热门商品缓存、浏览量异步回写、订单超时取消、CI、Docker 完整部署 |

## 核心验收标准

1. 游客可以访问商品列表和商品详情。
2. 用户可以注册登录并修改个人资料。
3. 用户发布商品后，商品必须先进入 `PENDING_AUDIT`。
4. 商品审核通过后才进入 `ON_SALE` 并可被购买。
5. 创建订单时必须通过条件更新锁定商品，避免重复购买。
6. 未支付订单取消后，商品恢复 `ON_SALE`。
7. 模拟支付成功后，订单变为 `PAID`，商品变为 `SOLD`，并生成支付记录。
8. 完成订单后才能评价。
9. 举报进入后台处理列表并记录处理结果。
10. 管理员关键操作必须写入操作日志。
11. 所有接口返回统一结构：`code`、`message`、`data`。
12. 不出现真实支付、微服务、复杂权限、高并发等超出边界的设计。
